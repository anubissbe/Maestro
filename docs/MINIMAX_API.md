# Official MiniMax API

In **Settings → Services**, add the separate **MiniMax Pay-as-you-go API Key**
and **MiniMax Subscription / Token Plan Key**. Credentials are stored in the
server's existing services configuration and masked in configuration responses.

For prompt enhancement, select **MiniMax M3 — Subscription / Token Plan** or
**MiniMax M3 — Pay-as-you-go** as the LLM provider. Maestro uses exactly that
provider's key; it never falls back to the other key. Provider-side quota and
credit-overflow rules still apply. Switching providers preserves a separately
configured local enhancer and remembers each provider's model choice. To use
M3 for ordinary prompt enhancement, leave the separate enhancer set to the
Director/default LLM option. With a dedicated local enhancer selected, ordinary
prompt improvement continues to use that local model. Models declaring their
own dedicated enhancer retain that override.

If switching back to Local previously left `MiniMax-M3` selected, see
[local prompt improver troubleshooting](LORA_SELECTION.md#local-prompt-improver-troubleshooting).

In **Studio → Video**, choose **MiniMax H3 API** under **Video engine**.
H3 supports text, first/last frames, and image/video/audio references. H3 Max
supports text and first/last frames. The controls restrict duration and resolution
to the selected model. Uploaded references are validated before submission.
Prompts and reference files are sent to MiniMax; video generation uses PAYG.
Studio keeps its usual prompt, Frames/References inputs, prompt improvement,
Generate/Queue buttons and gallery. The API engine translates those inputs to
H3; editing modes, intermediate keyframes and LoRAs require local generation.
H3 requests accept 4–15 seconds; fractional duration is rounded up by the API.

Director also has a **Video engine** selector. API mode uses the existing
planning/review flow, sends each shot and its references to H3 at 768P, trims
results to the planned timeline, and joins the clips. Images generated by the
image stage still use the configured image model. API video LoRAs are unavailable.
Saved projects retain their engine for resume and shot regeneration.

Cloud tasks are monitored server-side, including after closing the panel.
Successful videos and metadata are saved to the workspace selected at submission.
Task records are persisted in `app/settings/minimax_api_jobs.json`; pending tasks
resume monitoring when Maestro restarts. **Resume existing task** retries polling
or result download without submitting another generation. If submission status
is unknown, check the MiniMax console before making a new submission.

The official video API currently exposes no custom checkpoint or LoRA-upload
parameter. Use Maestro's local generation for CivitAI checkpoints and LoRAs.
Self-hosted H3 servers are a different integration.

Validation: `python -m unittest discover -s tests -p 'test_minimax_api.py'`.
These tests mock paid generation and cover credential isolation, submission
deduplication, rejected inputs, and recovery into the original workspace.

Director API soundtrack handling: each shot includes a cached WAV excerpt from
its position in the uploaded song, alongside the selected photo references.
The excerpt retains the original timing; only the unused tail of the rounded-up
API duration is padded with silence. The final joined video uses the original
song. Single-shot regeneration also uses that shot's original audio offset.
Audio references must fit H3's combined 15-second budget; incompatible additional
voice/style references are rejected before submitting any shot. This supplies
music and vocal timing to H3, but does not guarantee exact lip synchronization.
Existing submitted tasks retain their original input; use a new project revision
to generate with the added soundtrack conditioning.
